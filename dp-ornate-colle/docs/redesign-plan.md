# Redesign Plan — Dimpurr 个人主页视觉重做

> 范围：只改 `index.html` 的视觉与交互表现。信息架构、文案内容、`data/*.js`、图片资源一律不动。
> 硬约束保持：单文件、内联 CSS、vanilla JS、零依赖零构建；中英切换；xp 只排序不展示；设备按年份升序、null 显示 N/A；页脚四个链接内容不变；图片全部本地相对路径。

---

## 1. 设计方向

**关键词：白纸一样的底、呼吸感、一点淡蓝的凉意、衬线的温度。**

现在的问题是「深色高冷 + 机械等宽网格」，像展柜。新方向是「一本摊开的白色收藏手账」：
白底为主，用极浅的蓝灰色做分区衬底，卡片像贴在纸上的照片，圆角自然、阴影柔软、动效轻到几乎察觉不到。

- **白底 + 浅蓝灰分区**：body 纯白；intro 下方、收藏区、页脚之间用非常浅的 `#f6f9fc` 区块分隔，靠色块而非粗边框划分层次。
- **衬线做标题、无衬线做 UI**：现在 Playfair/Garamond 太正式（"端着"的主要来源）。换成 **Fraunces**（现代、暖、有手写感的衬线，只用于名字和区块标题）+ 系统无衬线栈（中文落到苹方/思源黑体系），UI 文案全部走无衬线，立刻"放松"下来。
- **圆角要"自然"**：不搞全站统一 8px/16px 的机械圆角。卡片用 `18px` 基础值，图片容器略小 `14px`，tabs 用胶囊形；个别重点元素（如 intro 区装饰）用非对称圆角（如 `24px 24px 24px 8px`）制造一点手绘感。全站圆角 token 化，控制在 3 档。
- **tab 配图标**：内联 SVG（零依赖），大 tab 用耳机/手机/游戏角色类线性图标，小 tab 可以纯文字。图标用 1.5px 描边线性风格，跟淡蓝点缀统一。

### 配色 token

```css
:root {
  --bg:        #ffffff;   /* 页面主底 */
  --surface:   #f6f9fc;   /* 分区衬底：极浅蓝灰 */
  --card-bg:   #fbfdfe;   /* 卡片图槽底：比 surface 更浅 */
  --ink:       #232d36;   /* 主文字：带蓝调的黑 */
  --muted:     #7d8b97;   /* 次要文字 */
  --faint:     #a8b4be;   /* 年份等三级文字 */
  --line:      #e4ecf2;   /* 分隔线：不用灰用蓝灰 */
  --accent:    #a9cbe8;   /* 点缀淡蓝：icon、hover、选中态 */
  --accent-ink:#5b8ab5;   /* 淡蓝上的可点击文字，保证对比度 */
  --shadow-card: 0 1px 2px rgba(35,60,90,.05), 0 6px 20px -8px rgba(35,60,90,.10);
  --r-lg: 18px;  --r-md: 14px;  --r-pill: 999px;
}
```

对比度自查：`--muted` on 白 ≈ 4.6:1（正文级达标）；`--accent` 只用于图形/装饰，正文级文字一律用 `--accent-ink`。

## 2. 布局与响应式策略

### 2.1 页面骨架（全断点通用）

```
┌─ 白底 ──────────────────────────────┐
│ intro（窄栏左对齐，max-width 560px）   │
├─ surface 浅蓝灰分区 ─────────────────┤
│ 大 tab（图标+文字，左对齐）            │
│ 小 tab（胶囊 chips，可横滑）           │
│ 卡片流（masonry / grid）              │
├─ 白底 ──────────────────────────────┤
│ footer 历代主页（小字横排链接）         │
└──────────────────────────────────────┘
```

语言切换按钮：保持右上固定，但改成胶囊白底描边小按钮，不再是黑底幽灵框。

### 2.2 容器宽度

现在 `max-width: 900px` 是"大屏显空"的根因。改为**分区容器**：
intro/footer 维持 `max-width: 640px` 阅读宽；收藏区容器 `max-width: 1280px`，2K/4K 下居中、两侧留白是设计的一部分而不是"空"。

### 2.3 两类图片混排：核心决策

素材盘点：
- 角色 31 张：原神 23 张 **2:1 横版**、绝区零 8 张 **1:1.6 竖版**（All 里混排）
- 设备 16 张：全部 **1:1 透明去背**

**方案选择：CSS 多列瀑布流（`column-count` + `break-inside: avoid`），只对角色区用；设备区用普通等宽 grid。**

理由：
1. 设备全是 1:1，等宽 grid 就是最优解，masonry 无意义。设备图槽给 `aspect-ratio: 1/1` + 浅色图槽底 + 内边距，透明去背图会显得很干净。
2. 角色区 2:1 和 1:1.6 高度差 3 倍多，等宽 grid 必然出现大量空洞或强行裁切；masonry 让每张图保持原始比例自然错落，正是这类"收藏墙"的标准解法。
3. 零 JS、零布局抖动：纯 CSS，图片加载前后不 reflow（每列宽度由 column-count 决定，高度随图自然撑开）。
4. 备选方案「grid-auto-rows + JS 计算 row-span」能保持**行优先**阅读顺序，但需要 JS 参与布局、窗口 resize 要重算、图片加载期会跳动——为了一个纯展示收藏页引入这些复杂度不值得（KISS）。

**代价与取舍（需要你确认，见 §5-1）**：CSS 多列瀑布流的填充顺序是**列优先**（先填满第一列再第二列），所以角色的 xp 倒序在视觉上变成"每列从上到下递减"，而不是"从左到右、从上到下"。xp 排序仍然生效、绝不展示数值，只是阅读动线变化。

### 2.4 断点表

| 断点 | 角色区列数 | 设备区列数 | 说明 |
|---|---|---|---|
| < 560px（手机） | 2 | 2 | 小 tab 横向可滑动；竖版立绘 2 列下高度可接受 |
| 560–900px（大手机/小平板） | 3 | 3 | |
| 900–1280px（iPad 横屏/laptop） | 4 | 4 | |
| > 1280px（2K/4K） | 5 | 5 | 容器 1280px 居中，列宽稳定在 ~230px，图不会糊 |

列宽稳定在 200–260px 区间：手机上不至于看不清立绘细节，4K 上也不会被拉伸得巨大空洞。grid-auto-flow: dense 不需要了（masonry 天然无洞）。

## 3. 动效（克制，参考 emilkowalski/skills 的规则）

只做三处，全部遵守「只动 transform/opacity、ease-out、150–250ms、stagger 30–60ms」：

1. **卡片入场 stagger**：tab 切换/首屏渲染时，卡片 `opacity: 0 → 1` + `translateY(8px → 0)`，每张延迟 40ms、250ms ease-out（`cubic-bezier(0.22, 1, 0.36, 1)`）。不阻塞交互。
2. **卡片 hover**：`translateY(-3px)` + 阴影加深 + 图片 `scale(1.02)`，180ms ease-out；**必须包在 `@media (hover: hover) and (pointer: fine)` 里**，避免触屏误触发。
3. **tab 选中态**：颜色过渡 150ms，小 tab 胶囊背景滑动（用 transition 不做 layout animation）。

全站 `prefers-reduced-motion: reduce` 时去掉位移、只保留 opacity 渐变。`transition: all` 一律禁止，写明属性。

## 4. 实施步骤

每步都是独立可验收的 diff，全部只动 `index.html`：

1. **Step 1 — 设计 token + 字体 + 页面骨架**：换字体链接（Fraunces + 无衬线栈）、`:root` token 全替换、body/main/footer 结构改成白底 + surface 分区、语言按钮重设计。此步完成后页面已是白底新版，只是卡片还是旧网格。
2. **Step 2 — Tab 系统**：大 tab 加内联 SVG 图标（设备=耳机、角色=人物/星星类）、重排大小 tab 视觉层级（大 tab 衬线标题式，小 tab 胶囊 chip 可横滑）。
3. **Step 3 — 卡片与混排**：设备区 1:1 等宽 grid + 浅图槽；角色区改 CSS 多列 masonry；卡片文字排版（名字/类别/年份的字号层级）重做；`card()` 函数只加 class 不动数据逻辑。
4. **Step 4 — 动效与打磨**：入场 stagger、hover、reduced-motion、焦点可见性（focus-visible 描边）、四个断点实测截图核对。

## 5. 需要你确认的取舍

1. **masonry 的阅读顺序**（最重要）：接受列优先填充（xp 顺序按列读），换零 JS、无抖动的瀑布流？还是坚持行优先、接受引入一段 JS 布局计算？我推荐前者。
2. **字体换血**：Playfair/Garamond → Fraunces + 系统无衬线。Google Fonts CDN 沿用现状（现页就在用，不算新依赖）。如果你更想保留现在的字体也行，但整体气质会偏正式。
3. **intro 区装饰度**：我想在 intro 加一点点非对称圆角色块/装饰线做"手账感"，克制到近乎没有。如果你要绝对素净，我就只做排版不加装饰。
4. **大屏列数上限**：5 列 @1280px 容器（列宽 ~230px）。你的 4K 屏如果想更饱满可以 6 列，但单列会偏窄、立绘细节变小。默认 5。
5. **图标风格**：大 tab 配线性 SVG 图标是默认项；如果你其实想要纯文字的高级感，也可以去掉，视觉会更"编辑风"。

## 6. 暗色模式与偏好持久化（第二次迭代）

### 6.1 暗色配色思路

暗色版不是「把白色反相」，而是同一气质的夜景：柔和的蓝灰深处（`#161d26` 打底、`#1c2530` 分区），不纯黑、不高对比，点缀淡蓝提亮到 `#7ba7cd` 保证暗底上的辨识度。

关键决策：**暗色下图槽（`--figure-bg`）保持浅色 `#f2f7fb`**。原因：
- 设备图是深色物体的透明去背图，放在深底上会直接「消失」；
- 原神卡池图本身烘焙了白色画幅，深底下若图槽也变深，白画幅会变成刺眼的亮块；
- 图槽保持浅色后，每张图就像「贴在夜色纸面上的照片」，与日间的「白底手账」是同一个隐喻，两套主题气质统一，且图片资源零处理。

### 6.2 跟随系统 + 手动优先

- 主题：默认读 `prefers-color-scheme`，并监听其变化实时跟随；语言：默认读 `navigator.language`。
- 用户一旦手动切换，写入 `localStorage`，之后以手动为准（系统变化不再覆盖）。
- 首帧 FOUC 防护：`<head>` 内联一段 3 行脚本，在 CSSOM 构建前把 `data-theme` 写到 `<html>` 上，暗色用户不会看到白屏闪一下。

### 6.3 论证：手动选择要不要记住？记在哪？

三个候选：

1. **不缓存（每次刷新回到跟随系统）**
   优点：实现最简、永远「智能」。缺点：对一个个人主页是真实痛点——很多人系统主题是日间、但逛网页时偏好暗色（或反过来）。不缓存意味着**每次打开都要重新点一下开关**，而个人主页是会被反复访问的页面，这个摩擦会重复发生。跟随系统只是好的「默认值」，不是好的「全部策略」。

2. **localStorage**
   优点：纯客户端、无过期概念、读写同步简单、`file://` 下也可用（本站主要用法就是磁盘直接打开）；隐私模式下抛异常，try/catch 静默降级为「不记忆」即可，不影响功能。缺点：跨浏览器/换设备不同步——但对个人主页这根本不算问题。

3. **Cookie**
   Cookie 的意义是「随请求发给服务端」。本站是纯静态页、没有任何服务端逻辑，Cookie 的每次请求都携带、过期管理、容量限制全是负担而无一处受益；且 `file://` 下 Cookie 行为不可靠。唯一可能的场景是将来上 CDN 做服务端主题渲染——那是引入服务端才需要考虑的事，与现状无关。

**结论：localStorage。** 它是「纯静态站记住用户偏好」的标准答案：零成本、零服务端、持久期合理、降级优雅。

附带决策：手动选择**永久生效**，不提供「恢复跟随系统」的 UI。理由：两个开关（日/夜、中/英）本身语义已经够直白，再加第三种隐形态（「自动」）会让一个个人主页的 UI 变复杂，违背 KISS；想恢复自动的用户清一下站点数据即可，这个成本可以接受。
