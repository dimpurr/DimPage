⚠️ **数据还会小幅变动**（Dim 正在 review 城市名和分类），但**字段名和结构不会变**。按 schema 写，别把具体条目写死进代码。

图片在 `img/places/*.webp`，是城市风景/地标照片，**横构图**（和现有的设备透明底图、海报竖图都不一样，布局要重新想）。少数条目可能暂时缺图，要有优雅的降级。

## 3. 要做的三件事

### ① 大 tab「去过的地方」
- `key: 'places'`，英文 `Places I've Been`，中文 `去过的地方`
- 配一个图标（地图/图钉/地球，你定）

### ② 左边：子 tab（minors，互斥，沿用现有机制）
`all` / `live`(居住) / `travel`(旅游与活动)

### ③ 右边：**视图切换**（这是这次唯一的新机制）
Dim 的原话：

> 右边可以切换视图（和其他一致的卡片视图，直接搜索城市风景图或封面图）或者地图视图（或者什么好的解决方案）

所以至少两个视图：
1. **卡片视图** —— 和页面其他 tab 观感一致，但适配横构图城市照。默认视图。
2. **地图视图** —— 用 `lat`/`lon` 把城市点在世界地图上。

⭐ **地图技术方案你自己定，不设限制。** Dim 明确说了：

> 没必要一定追求"零依赖"，这个要求不合理。我们只是尽量减少依赖、别搞太复杂。挂个 CDN 或者挂一个静态 JS 文件，只要 ROI 够高都可以。反正原始数据很清晰，这个地图以后就算挂掉了也无所谓 —— 更别说存成本地 JS 文件根本不会挂，CDN 也没那么容易挂，总能找回来还原。让他根据设计最优解思考技术方案就行。

所以 **Leaflet / MapLibre / D3-geo / topojson 这类都可以用**，按「什么方案做出来最好看、最合适」来选。两个务实建议：
- **优先把库 vendor 进仓库**（下载成 `vendor/xxx.js` 一起 commit）而不是纯挂 CDN —— 这是个存档仓库，本地打开也要能用。但真觉得 CDN 更划算也行。
- 底图瓦片如果要联网拉，考虑离线时的降级表现。

可行方向（自己判断，也欢迎更好的想法）：
- Leaflet / MapLibre + 简洁风格底图，marker 点开弹卡片
- D3-geo + topojson 画一张配色贴合本站的极简世界地图（无瓦片、纯矢量，最容易做得好看且完全离线）
- 手写内联 SVG 等距圆柱投影（`x=(lon+180)/360`, `y=(90-lat)/180`）—— 最轻但最土
- 时间轴视图（按 `first` 年份排的横向轴）作为第三视图 —— 数据里有 `segs`，很适合

> 如果你觉得还有更棒的视图（第三个、第四个），**可以加**。这是 Dim 明确允许的。

**视图切换按钮放哪、长什么样，你自己设计**，只要求和左边的子 tab 在同一行、视觉上分得清「筛选」和「视图」是两种不同的操作。
