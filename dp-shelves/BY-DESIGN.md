# BY-DESIGN — 看起来像 bug，其实是刻意的

> 觉得下面哪条「坏了」、想动手之前先读完那一条。每条：看起来像 / 实际是 / 别做 / 失效条件 / 证据。

## 1. 多来源卡片不是链接，选择层点了才生成
- **看起来像**：单来源卡片是 `<a>`，多来源卡片却是 `<div role="button">`，选择层也不预先写进 DOM，不统一。
- **实际是**：iPad Safari 上，`<a>` 里嵌 `<a>` 会把 DOM 拆坏；圆角 / overflow:hidden / transform 容器里的 `backdrop-filter` 会把模糊漏到整页并吞掉点击，多来源卡片因此点不开（真机报过）。
- **别做**：把多来源卡片改回 `<a>`；在卡片或选择层里加 `backdrop-filter`；把选择层预埋进每张卡片。
- **失效条件**：不再有多来源条目，或 WebKit 修好这两个问题并实测过（Playwright WebKit「iPad Pro 11」）。
- **证据**：`index.html` 的 `openPick`、`data-multi`；样式里 `backdrop-filter` 只用在顶栏。

## 2. 同一首歌收了好几条
- **看起来像**：重复数据，该去重。
- **实际是**：故意收同一首歌的不同「身体」：原版 MV、MMD、翻跳 / 原创编舞，各是一条。
- **别做**：按曲名合并，或把翻跳并进原版当第二个来源。
- **失效条件**：收藏主人说要合并。
- **证据**：「Gimme×Gimme」在音乐和舞蹈架各有条目。来源合并只看「同一视频的 B 站 / YouTube 两个源」（`find_same`：时长差 ≤4 秒且「」内文字相同）。

## 3. 副标题顶替了 UP 主
- **看起来像**：卡片第二行有时是 UP 主，有时不是，不一致。
- **实际是**：上传者通常是搬运号，没有意义。有 `sub` 就显示 `sub`（作者、原名 · 年份 · 集数），没有才回落 UP 主。
- **别做**：把 UP 主「修回」第二行，或把 `sub` 塞进标题。
- **失效条件**：无。
- **证据**：`index.html` 里的 `i.sub ?? i.uploader`。

## 4. 封面文件名带 `-v2` / `-v3`
- **看起来像**：命名乱。
- **实际是**：`covers/` 在 nginx 上缓存 30 天，换封面必须换文件名，否则访客看到旧图。`shelf.py cover` 自动递增版本号并删掉旧文件。
- **别做**：手动把新图覆盖到原文件名上。
- **失效条件**：去掉 `covers/` 的长缓存。
- **证据**：`cmd_cover` 里的 `-v(\d+)`。

## 5. 「听歌」架是方块，封面是专辑图
- **看起来像**：和其它架不一样宽、封面不是视频截图。
- **实际是**：这一架收几乎没画面的歌，按专辑墙显示；只有收藏主人明说的才放进来。
- **别做**：按「画面少」自己把歌挪进来；把这一架改回 16:9。
- **失效条件**：收藏主人改主意。
- **证据**：`index.html` 的 `SQUARE`，`shelf.py` 的 `SQUARE_SHELVES`。

## 6. 特摄放在「番剧」架
- **看起来像**：放错了，真人特摄不是动画。
- **实际是**：特摄长期只会有一两部，单开一架太空；「番剧」是 B 站的叫法，本来就包括特摄。用 `特摄` 标签区分。
- **别做**：为特摄新开一架。
- **失效条件**：特摄条目多到值得单开一架。
- **证据**：`ウルトラマンテオ` 条目带 `特摄` 标签。

## 7. 分 P 合集的时长是 0
- **看起来像**：时长丢了。
- **实际是**：分 P 合集（整季番剧之类）只拿得到第一 P 的时长，显示出来是错的，所以置 0 不显示；标题里的「 p01 …」也会被去掉。
- **别做**：把第一 P 的时长填回去。
- **失效条件**：能拿到合集总时长。
- **证据**：`probe` 里的 `p0*1` 处理与 `bili_fallback` 的 `videos > 1`。
